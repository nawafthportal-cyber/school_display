# فيديو ربط أول شاشة

يسجل `build_pairing_video.py` واجهات Django الفعلية داخل متصفح Chromium، مع
نصوص عربية وأسهم وإطارين للجوال والتلفاز. لا يستخدم صورًا مولّدة لواجهات المنتج.
الفيديو دون صوت، وتُحفظ التوضيحات داخل الصورة وفي ملف WebVTT مستقل.

يغطي المتطلبات، إنشاء الشاشة أو استخدام الموجودة، QR، الرمز اليدوي، الرابط
المباشر، المعاينة، نقل ارتباط جهاز سابق، التحقق من الاتصال، وإكمال بيانات المدرسة
والتوقيتات والجدول اليومي.

## إعادة التسجيل

استخدم نسخة مستقرة من المصدر مع ترحيلات قاعدة بيانات مكتملة. تحتاج بيئة التطوير
إلى Playwright مع Chromium وPillow وcryptography، وإلى FFmpeg يدعم libx264.
هذه متطلبات أداة التسجيل فقط، ولا تضاف إلى متطلبات تشغيل الموقع.

```powershell
.\.venv\Scripts\python.exe tools\tutorials\build_pairing_video.py --ffmpeg 'C:\path\to\ffmpeg.exe' --rehearsal
.\.venv\Scripts\python.exe tools\tutorials\build_pairing_video.py --ffmpeg 'C:\path\to\ffmpeg.exe'
```

تُنشئ الأداة قاعدة SQLite وبيانات مدرسة تجريبية في مجلد مؤقت جديد، وتعطّل قراءة
ملف `.env` واستخدام البريد وRedis الخارجيين. يشير Chromium وحده إلى خادم HTTPS
محلي على `127.0.0.1:443` بدل نطاق الموقع. يلزم أن يكون هذا المنفذ متاحًا؛ لا
تغير الأداة DNS النظام أو شهاداته. يسمح تضمين الصفحات داخل الإطار في إعدادات
التسجيل المؤقتة فقط؛ لا تغيّر إعداد منع الإطارات في الموقع.

ينفذ `--rehearsal` الرحلة كاملة بسرعة للمراجعة دون استبدال ملفات الفيديو النهائية.
توجد لقطات المراجعة وسجل المشاهد وتوقيتاتها في المجلد المؤقت المطبوع عند التشغيل.

الملفات النهائية في `static/videos/`:

- `first-screen-pairing-ar.mp4`: فيديو H.264 بدقة 1920×1080 مع faststart.
- `first-screen-pairing-poster.jpg`: صورة الغلاف.
- `first-screen-pairing-ar.vtt`: التوضيحات العربية.
- `first-screen-pairing-chapters-ar.vtt`: توقيت أقسام الفيديو.

بعد إعادة التسجيل، طابق أزرار `data-tutorial-seek` في
`templates/dashboard/_screen_pairing_tutorial.html` مع توقيت الأقسام المولّد،
وحدّث رقم النسخة في روابط الأصول. راجع المشاهد الناتجة وتشغيل MP4 والانتقال بين
الأقسام على الجوال والحاسب قبل نشر إصدار الموقع.
